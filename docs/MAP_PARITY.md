## Известные расхождения и риски

- **Проверка PWA в браузере 03.10 (preview :5177, локальные данные, без входа в аккаунт):** карточка станции — подпись норм, курсор в конец, км сохраняется; карта, автоподбор и перетаскивание вживую не гонялись (нужен вход в аккаунт/долгое нажатие мышью, инструмент браузера его не умеет).
- На Android в логах остались диагностические `Log.w` в `ServicePhaseAutoFillViewModel.kt` (без данных, только классы исключений) — решить, оставить ли.

- Раунд 2 прошёл автопроверки: Android `:domain:test`, `:features:route:testDebugUnitTest`,
  `:features:route:compileDebugKotlin`, `:app:assembleDebug`; PWA — unit/payment/smoke тесты (80 unit),
  production build и lint затронутых файлов. Порядок выкатки #27/#28: сервер (6461994, 438c940, cc92057) → Android/PWA.
- 04.10 экран #27 повторно проверен на локальных Android/PWA-стендах с реальными полилиниями
  серверного графа: маршруты идут по рельсам, клиенты рисуют весь `geometry`, а не прямые
  отрезки между станциями. По решению пользователя все линии одной толщины; выбранная непрозрачна и поверх.
- Зависимость `maplibre-gl` (~1 МБ) в PWA попадает в precache сервис-воркера — пользователь решил оставить.
- Android «предзагрузки карты» нет: тайлы кэширует сама MapLibre (`mbgl-offline.db`), офлайн-областей нет.
- Конфиг nginx PWA — bind-mount одного файла: правка на хосте применяется только после `docker restart
  loco-driver-pwa` (см. память `reference_pwa_nginx_bind_mount`).

## Как вести таблицу

1. Любое изменение поведения сначала в `SCREEN_SPECS.md` (master), потом строка здесь, потом задания исполнителям.
2. Статус меняется только после проверки; в колонку «Проверено» пишется уровень (К/Т/Ж) и кто/когда.
3. Расхождение кода и спеки — баг. Вынужденные отличия PWA (веб-ограничения) фиксируются отдельной строкой с причиной.
