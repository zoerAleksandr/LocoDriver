### Принятые решения (не пересматривать без причины)
- Мёртвый код Android (помечен «🚫» в спеке) в iOS **не переносится**.
- Баги Android (BUG-NN) переносятся **как есть** ради паритета; список в
  приложении спеки остаётся на ручную проверку — там не всё однозначно.
- Оплата в iOS — **Robokassa** (Apple Pay и IAP в РФ не работают). Паролей
  мерчанта в клиенте нет: оплата идёт через серверный checkout
  (`POST /robokassa/checkout` в бэкенде, Android уже переведён).
- `nightTimePercent` в UI не редактируется.
- Стиль — по iOS-макетам и дизайн-киту; если элемента нет в макете — собирать из
  компонентов кита по логике спеки; содержание и поведение — строго по спеке.
- Если в макете несколько вариантов экрана (Paywall A/B/C, Stats A/B/C) —
  выбирать ближайший к текущему Android-экрану и указывать выбор в PR.

### Что показала практика
- Облачные сессии **не умеют собирать iOS** (нет Xcode/Swift). Тем не менее и
  #143, и #144 собрались с первого раза — промпты с жёсткими рамками работают.
- Обязательная проверка каждого PR локально: `xcodebuild` под симулятор +
  запуск на iPhone 17 Pro (симулятор) + прогон ключевых сценариев экрана.
- Одна сессия экранной волны дорогая: облачного кредита $100 хватило примерно
  на 7 сессий (4 аудита, консолидация, этап 0, главный экран). Локально на Pro
  одна сессия волны — по оценке 20–40% недельного лимита, на Sonnet дешевле.

## 2. Как запускать сессию волны

1. Убедиться, что предыдущие PR волны смержены (сессии стартуют от `master`).
2. Новая сессия (облако или локально; локально — лучше модель Sonnet).
3. Промпт = **общий блок** (ниже) + **блок задачи** (§3).
4. Локально заменить в общем блоке строку про отсутствие сборки на:
   «Сборка есть: после работы собери `xcodebuild` под симулятор и исправь ошибки».
5. Проверка PR: сборка, симулятор, чек-лист спеки из описания PR, затронутые BUG-NN.
6. Мерж. PR внутри волны независимы, порядок мержа любой.

### Общий блок промпта

```text
Контекст: iOS-версия LocoDriver (нативный SwiftUI). Фундамент готов: дизайн-кит iosApp/iosApp/Shared/Design, компоненты Shared/Components, навигация Navigation/ (AppRoute, AppSheet, AppRouter, StubView). Xcode-проект — синхронизируемая папка: новые .swift-файлы попадают в таргет сами, project.pbxproj не трогать.

Прочитай перед работой: CLAUDE.md, AGENTS.md, docs/IOS_PLAN.md, docs/IOS_UI_GUIDE.md (правила обязательны), свои разделы SCREEN_SPECS.md, iOS-макет своего экрана в design/src/*.jsx, Android-эталон (файлы из строк «Источник:» спеки).

Правила:
- Содержание и поведение — строго по SCREEN_SPECS.md. Внешний вид — дизайн-кит + iOS-макет. Нет в макете — собрать из компонентов кита по логике спеки. Макет противоречит спеке — права спека.
- «🚫 Мёртвый код Android» — не делать. Баги Android (BUG-NN) — переносить как есть, в PR перечислить, какие BUG-NN затронуты.
- Логика и расчёты — через Kotlin (domain/UseCase/iOS-ViewModel в iosApp/src/commonMain/.../viewmodel по шаблону из AGENTS.md), не переписывать на Swift. Новую iOS-VM зарегистрировать в iosUseCaseModule и IosViewModelHelper — только ДОБАВЛЕНИЕМ строк.
- Трогать только файлы своего экрана. Общая зона (Shared/Design, Shared/Components, Navigation, IosViewModelHelper, iosUseCaseModule) — только добавление; не хватает компонента — добавь новый файл в Shared/Components, существующие не меняй.
- SCREEN_SPECS.md не менять, кроме коротких iOS-примечаний в своём разделе; iOS-подробности — в docs/IOS_UI_GUIDE.md.
- Deployment target iOS 16.0. Сборки iOS в этой среде нет — пиши консервативно; всё, в чём не уверен, перечисли в PR.
- Обязательно: ветка ios/<имя-задачи> от master, коммит, push и PR в master. В PR: чек-лист пунктов спеки «сделано / нет / отклонение», затронутые BUG-NN, что не проверено.
```
