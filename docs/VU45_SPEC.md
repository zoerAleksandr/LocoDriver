# ВУ-45 — инструмент «Справка ВУ-45» (спецификация, реализовано на Android)

Статус: **реализуемо и реализовано** (ветка `feature/vu45`). Поведение экрана — `SCREEN_SPECS.md` §26; здесь — предметная часть:
формулы, таблицы, примеры, источники, оговорки.

## 1. Что такое ВУ-45

Справка об обеспечении поезда тормозами и исправном их действии (не расход топлива/энергии). Осмотрщик вагонов выдаёт её машинисту
ведущего локомотива после полного опробования тормозов (п. 9.2.6 Инструкции). Машинист по ней сверяет требуемое и фактическое
нажатие колодок и выбирает скорость. В справке: время выдачи, серия/номер локомотива, дата, номер поезда, вес, всего осей, **требуемое
нажатие колодок, ручные тормоза в осях (потребные/наличие)**, таблица «нажатие на ось × число осей × нажатие колодок» (значения на ось
в бланке: 1,25 / 2,5 / 3,5 / 5 / 6 / 6,5 / 7 / 8 / 8,5 / 9 / 10 / 12 / 14 / 15 / 16 / 18 тс), плотность тормозной сети, хвостовой вагон,
доля композиционных колодок (К-75 / К-100), выход штока хвостового вагона, давление в ТМ хвоста и др.

## 3. Формулы

Обозначения: `Qс` — вес состава (тс), `Qл` — учётный вес локомотива (если учитывается), `Q = Qс + Qл`, `N` — норма табл. 1 (тс на 100 тс).

1. **Потребное нажатие** `Па = N × Q / 100` (тс, в пересчёте на чугунные колодки). Для **грузовых** поездов вес и нажатие локомотива не
   учитываются (п. 6.3); для пассажирских/грузопассажирских — учитываются (табл. 4, 5).
2. **Фактическое нажатие** `Факт = Σ (нажатие на ось_i × число осей_i) + нажатие локомотива` (табл. 3 — вагоны, табл. 4 — локомотивы).
   `Факт/100 = Факт × 100 / Q`. **Достаточно**, если `Факт ≥ Па`.
3. **Допускаемая скорость:**
   - `Факт/100 ≥ N` → скорость табл. 1: числитель — спуск до 0,010 включительно, знаменатель — круче 0,010 до 0,015 (для п. 11.3-11.6 до 0,012);
     «−» — норм нет, скорость устанавливает начальник дороги. Значение в скобках — автоблокировка с 3-значной сигнализацией, зелёный огонь
     АЛСН, спуск не круче 0,010 (п. 3.1).
   - `Факт/100 < N`, но `≥ минимума табл. 2` → **п. 4.4**: скорость табл. 1 (без скобок) уменьшается на **2 км/ч** за каждую недостающую
     тонну (грузовые, рефрижераторные, хозяйственные); для пассажирских, грузопассажирских и рефрижераторных >90 км/ч — на **1 км/ч** при
     спуске до 0,006 и **2 км/ч** при спуске круче 0,006 до 0,015; результат — вниз до кратного 5. Применимо только в случаях п. 4.2-4.3
     (отказ автотормозов в пути, особые составы). *Недостающие тонны берутся с округлением вверх — решение реализации (в тексте Норм не
     уточнено), безопасная сторона.*
   - `Факт/100 <` минимума табл. 2 → скорость по таблицам не определяется (п. 5.1: устанавливает начальник дороги, на 20 % ниже номограмм).
   - **П. 3.3:** груженый грузовой поезд с вагонами с нагрузкой от колёсной пары > 21 тс, все автотормоза включены, ВР на среднем режиме,
     композит: **К-75** (≥ 75 % вагонов) и нажатие `< 33`, но `≥ 31` → до 80 км/ч; **К-100** и `< 31`, но `≥ 30` → до 80 км/ч.
4. **Ручные тормоза** (п. 7, табл. 6; грузовые, рефрижераторные, хозяйственные, грузопассажирские, почтово-багажные): потребно
   `⌈ Qс × k / 100 ⌉` осей, где `k` — норма на 100 тс. **Единое наименьшее k = 0,6** (в пределах двух и более дорог) — значение по умолчанию.
   По табл. 6 (уклон → оси на 100 тс): до 0,006 → 0,4; 0,008 → 0,6; 0,010 → 0,8; 0,012 → 1,0; 0,014 → 1,2; 0,016 → 1,4; 0,018 → 1,6;
   0,020 → 1,8 (круче — только башмаки). Пользователь выбирает `k` на экране, выбор запоминается (SharedPreferences). Для пассажирского поезда
   ручные тормоза приводятся в действие у **всех** вагонов — не нормируются. *Округление вверх — решение реализации.*
5. **Расчёт без подсчёта (п. 6.4):** при 100 % исправных тормозов потребное нажатие принимается 60 тс/100 тс для электропоездов, дизель-поездов
   ДР1/Д, АЧ2, пассажирских поездов с пассажирскими локомотивами любых серий и локомотивами ВЛ80, ВЛ10, ВЛ11, ВЛ65, ВЛ82 и цельнометаллическими
   составами (до 120 км/ч); 33 тс — сплотки метро (до 75 км/ч). В этом случае в справке таблица не заполняется. Экран всегда считает по таблицам.

## 5. Примеры расчёта

1. Груженый грузовой, Q = 3040 тс, 128 осей композит груженый (8,5): `Па = 33×3040/100 = 1003,2 тс`; `Факт = 128×8,5 = 1088 тс` (35,79 на 100 тс) → достаточно,
   80 км/ч (90 при автоблокировке на спуске ≤0,010); ручных осей `⌈3040×0,6/100⌉ = ⌈18,24⌉ = 19`.
2. Те же 128 осей, чугун груженый (7,0): `Факт = 896` (29,47 на 100 тс) → не хватает 107,2 тс; недостаёт `33−29,47 = 3,53` → 4 т → `80 − 2×4 = 72 → 70 км/ч`.
3. 100 осей чугун: 700 тс = 23 тс на 100 < 28 → скорость по таблицам не определяется.
4. Пассажирский до 120, состав 800 тс (64 оси × 10,0) + локомотив 184 тс (8 осей × 14,0): `Q = 984`, `Па = 60×984/100 = 590,4`, `Факт = 640+112 = 752` → достаточно, 120 км/ч.
5. П. 3.3: 1000 тс, нажатие 31,5 на 100 тс, К-75 → 80 км/ч; 30,5 при К-75 → п. 4.4: 3 т → 74 → 70; 30,5 при К-100 → 80.

Примеры покрыты юнит-тестами: `domain/src/commonTest/kotlin/com/z_company/domain/brake/BrakeCertificateCalculatorTest.kt` (11 тестов).

## 6. Реализация

- `domain/.../brake/BrakeNorms.kt` — таблицы; `BrakeCertificateCalculator.kt` — чистая логика (commonMain, без java.*).
- `features/route/.../ui/BrakeCertificateScreen.kt` (Compose, примитивы `SettingsUnifiedUi`), `viewmodel/BrakeCertificateViewModel.kt`,
  `navigation/BrakeCertificateDestination.kt`, `BrakeCertificateRoute` (query-аргументы `weight`, `axles` для предзаполнения).
- `Router.showBrakeCertificate(weight, axles)` (по умолчанию no-op; реализация в `RouterImpl`), карточка «ВУ-45» в `HomeScreen` после «Статистики».
- Хранение: **нет** (только SharedPreferences `brake_certificate_prefs`: норма ручных тормозов). Сервер/JSON/БД не затронуты. Для всех пользователей.
- iOS: не реализовано (метод Router по умолчанию no-op; логика в `domain` готова для переиспользования).
