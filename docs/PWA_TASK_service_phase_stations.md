## 1. Данные и синхронизация (сделать первым)

### 1.1 Плечо `UserSettings.servicePhases[]` — новые поля (аддитивные)
```
ServicePhase {
  id, departureStation, arrivalStation, distance (Int, может быть 0), linearMileageRate,
  intermediateStations: [ServicePhaseStation],   // по порядку от отправления
  departurePoint: ServicePhasePoint | null,       // координаты крайних
  arrivalPoint:   ServicePhasePoint | null
}
ServicePhaseStation { id, name, latitude?, longitude?, kmFromStart?, kind: "station"|"halt",
                      esr?, osmId?, source: "manual"|"osm"|"map" }
ServicePhasePoint { latitude, longitude, osmId?, esr? }
```
**Важно (сейчас это баг потери данных в PWA):** `SettingsView.vue` при сохранении плеча
собирает объект заново из 5 полей и теряет `intermediateStations`/точки. Сохранять плечо
целиком (spread исходного + правки). Сервер сохраняет поля, не присланные клиентом, но локальная
копия PWA их теряет. В рейс (`Train.servicePhase`) станции и точки **не копировать**.

### 1.2 Справочник станций = записи норм `/v1/norma_time/stations/` (full replace) — новые поля
```
{ stationId, name, appearanceToStartMin, endToBarrierMin, barrierToStartMin, endToWorkEndMin,
  hasGeoFields: true,                 // ОБЯЗАТЕЛЬНО слать всегда (маркер нового клиента)
  latitude?, longitude?, esr?, osmId?, kind?: "station"|"halt",
  axisKm?: Int, axisPk?: Int (1–10), updatedAt }
```
Сервер перезаписывает геополя **только при `hasGeoFields: true`**; без маркера (как PWA сейчас)
координаты сохраняются. Как только PWA начнёт хранить геополя — слать маркер и все поля
(null = стёрто). Хранить геополя в Dexie (миграция схемы БД PWA). `UserSettings.stationList`
остаётся списком названий для выпадающих списков.

### 1.3 Справочник — единый источник координат (как `StationDirectory.kt`)
- Связь по названию: `normalize = trim + ё→е + lowercase + схлопнуть пробелы`.
- Чтение плеча: где у станции справочника есть координаты — они (крайние и промежуточные),
  иначе копия из плеча.
- Сохранение плеча: координаты из плеча пишутся в справочник (новые станции создаются записью;
  у существующих обновляются координаты/ЕСР/osmId/тип; нормы и км оси не трогать).
- Один раз за запуск — перенос координат из старых плеч в справочник только туда, где их нет.

## 2. API (прод, Bearer-токен; лимит 200 запросов/час на пользователя, 429 + Retry-After)

- `POST /v1/service_phase/stations/suggest`
  `{departureStation, arrivalStation, country, departureOsmId?, arrivalOsmId?, departurePoint?{latitude,longitude}, arrivalPoint?}`
  → `{status: ok|ambiguous|not_found|no_path, side?, name?, candidates?, approximate?, departure?, arrival?, lengthKm?, stations?[{name,kind,esr,osmId,latitude,longitude,kmFromStart}]}`.
  Если у крайней станции есть координаты (справочник/плечо) — **передавать `departurePoint`/`arrivalPoint`**:
  путь и км считаются от них (иначе от точки OSM, расхождение до нескольких км).
- `POST /v1/service_phase/stations/lookup` `{name, country, near:[{latitude,longitude}]}`
  → `{candidates:[{osmId,name,kind,esr,operator,region,latitude,longitude,neighbours[],approximate?}], approximate}`
- `POST /v1/service_phase/stations/nearest` `{latitude, longitude, radiusM}` → `{station|null}`
- `POST /v1/service_phase/route/length` `{points:[{latitude,longitude}…], withGeometry?: true}`
  → `{lengthKm, kmAt:[км каждой точки], geometry?:[[lat,lon]…]}`; 404 (не «Not Found») = путь не найден.
  Путь — один непрерывный по рельсам через все точки (на сервере, клиенту ничего считать не надо).
- **Сокращения** («Гатчина ТБ», «СПбСМ»): если точного совпадения нет, lookup/suggest возвращают
  похожие с `approximate: true`. **Неточный вариант никогда не подставлять сам** — только выбор.

## 3. Экраны и поведение (детали и тексты — SCREEN_SPECS §6.6/§17.4)

### 3.1 Справочник станций (StationsListView / StationEditView)
- Список: значок-метка у станций с координатами.
- Карточка: блок «КООРДИНАТЫ» — статус (зелёная/оранжевая точка, «Координаты есть» + `lat, lon · ЕСР …`
  / «Нет координат» + пояснение), кнопка-строка без шеврона «Определить автоматически»/«Определить заново»
  (lookup; одна находка — применить и показать «Нашлась: … Если это не та станция — укажите точку на карте
  вручную.»; несколько или неточные — шторка выбора, после выбора «Выбрать другую»), строка «Указать/Уточнить
  на карте» (выбор точки). Без текста под блоком.
- Блок «КИЛОМЕТРАЖ»: два поля ввода в ряд на всю ширину — число с постфиксом «км»/«пк» сразу после числа,
  пусто — тусклые «км»/«пк»; км ≥ 0, пикет 1–10, пикет только при заданном км. Подпись «Ось станции по ж/д километражу.»
- Нормы: под блоками приёмки/сдачи подпись «Нормы выше используются автоматически…». Поля норм:
  при открытии ввода **курсор в конец, без выделения** (сейчас `@focus="e.target.select()"` — убрать
  в StationEditView и SeriesEditView), 0/не задано — пустое поле.
- Удаление названия из выпадающих списков (крестик) убирает только название из `stationList`;
  запись с данными (нормы/координаты/км) остаётся. Удаление из карточки — и запись, и название.

### 3.2 Редактор плеча (сейчас форма в SettingsView — переделать в отдельный полноэкранный экран)
- Шапка: слева «Готово», по центру «Новое плечо»/«Редактировать плечо», справа «Карта».
- **Автосохранение** (~0,6 с после правки и при закрытии), кнопки «Сохранить» нет. Сохраняется,
  когда заполнены обе станции (расстояние не обязательно, пусто = 0). У нового плеча один id на всё
  редактирование; обратное плечо — при закрытии; без правок не сохранять.
- Поля станций с автодополнением, «Расстояние, км», «Доплата за пробег, {валюта}/км» (валюта по стране).
  В строке «Измерить по карте» справа — «За плечо: {расстояние × ставка} {валюта}» (копейки, как в расчёте).
- «Измерить по карте» (иконка — две метки, соединённые путём): route/length по крайним + промежуточным
  с координатами; км промежуточных обновляются по тому же пути. Крайняя без координат — сначала lookup по
  названию (неточные — шторка выбора, после выбора замер продолжается), после замера снекбар «Координаты
  станции «…» определены автоматически — проверьте, что точка верная» + «Проверить». Чип «Измерено по карте»
  (признак локально, ключ — расстояние + подпись координат).
- Схема станций (всегда видна): крайние кликабельны (шторка крайней станции с координатами), промежуточные —
  добавить/вставить между/править (название, станция/о.п., км, координаты: найти/на карте)/удалить с
  «Отменить»/перетаскивание. Подсветка «нет координат».
- «Найти автоматически» (suggest): загрузка по шагам, уточнение неоднозначной/неточной крайней станции,
  предпросмотр со слиянием с существующими станциями, переименование, «Установить N км». Автоподбор
  **только дописывает** координаты: станции, известные справочнику, и крайние с точками сохраняют свои.
- Карта плеча: станции с подписями, линия **только по рельсам** (route/length + withGeometry); пока строится —
  карточка «Строим путь по рельсам…» со спиннером; ошибка — понятный текст причины (+ «Повторить» при сбое сети);
  линию напрямик не рисовать. Кэш линии на устройстве по набору точек. «+», «−», «Моё местоположение»,
  в шапке «N станций» / «Показано X из Y · у Z нет координат».
- Выбор точки на карте: карта под неподвижной меткой, станции OSM на карте, соседние станции плеча — ориентиры.
- Карта: MapLibre GL JS + стиль `https://tiles.openfreemap.org/styles/liberty`, ж/д слои из источника
  `openmaptiles` (transportation class=rail; poi class=railway subclass station|halt, станции видны с z14),
  шрифт «Noto Sans Regular». (Зависимость согласовать.)

### 3.3 Форма поезда
- Шторка выбора плеча: сортировка — последнее использованное с текущей станции → другие с неё → по частоте.
- Подсказки станций: ближайшая по GPS → по частоте → остальные (координаты — справочник + плечи).
- Название новой станции по GPS (разовый фикс по нажатию, `navigator.geolocation`): правила
  `ServicePhaseStationPicker.nameForNewStation` — в 500 м от станции плеча → она; стоя на месте (сдвиг
  < 300 м от прошлого добавления) → ближайшая станция плеча; в движении → ближайшая станция плеча впереди
  последней записанной (2 км); без плеча с координатами → ближайшая известная (справочник+плечи, 2 км),
  иначе `/stations/nearest`; повтор предыдущей станции не подставлять; если пользователь уже ввёл — не трогать.
- Вес/оси/У.Д./расстояние: «0»/«0.0» из БД и синхронизации (сервер пустые хранит как 0) показывать **пустыми**
  (сейчас `TrainEditView` показывает «0» для веса/осей; нормализовать при загрузке поезда, не при вводе).

### 3.4 Ошибки сети (везде в этой фиче)
Нет сети (`navigator.onLine === false` / сетевая ошибка без ответа при оффлайне) → «Нет подключения к интернету»;
сеть есть, сервер недоступен → «Нет связи с сервером — проверьте подключение к интернету»; 429 → «Слишком много
запросов — попробуйте позже»; «Сервис не ответил — попробуйте позже» — только ошибка сервера/таймаут 30 с.

## 5. Перетаскивание элементов (отдельная часть, можно делать независимо от 1–4)

Эталон — SCREEN_SPECS: §6 «Поезд» (строки станций), §2 «Локомотив» (порядок секций), §… «Главная»
(перестановка плиток текущего маршрута), §6.6 (станции плеча). Android: `component/LongPressDrag.kt`
(`detectReorderDrag`, `reorderStep`), `TrainStationTimeline`, `FormLocoScreen`, `HomeScreen`.
Сейчас в PWA перетаскивания нет нигде. Библиотеку (например SortableJS) — только после согласования;
допустимо и своё на Pointer Events.

### Общий жест (для всех списков)
- **Долгое нажатие (~400–500 мс) в любом месте элемента — и тянуть, одним движением**, без отдельной
  ручки. Без долгого нажатия палец прокручивает экран как обычно (на тач-устройствах); тап — обычное действие элемента.
- После старта перетаскивания жест принадлежит только ему: не срабатывают свайп «Удалить», тапы, поля
  ввода, прокрутка страницы (`touch-action: none` на время жеста, `preventDefault`, захват указателя
  `setPointerCapture`). На старте — тактильный отклик (`navigator.vibrate(10)`, где есть).
- Элемент едет за пальцем; **сосед меняется местами, когда перетаскиваемый заходит на половину его
  высоты (ширины)**; смещение компенсируется на размер соседа + промежуток — без прыжков (как `reorderStep`).
- У краёв видимой области — автопрокрутка, удерживаемый элемент остаётся видимым.
- Ключ элемента в `v-for` — стабильный id (смена ключа посреди жеста рвёт его).
- Мышь (десктоп): то же, долгое нажатие ЛКМ или сразу перетаскивание с порогом сдвига — на выбор, главное не ломать клики.

### Где
1. **Станции поезда** (TrainEditView, таймлайн): станция едет вместе с перегоном под ней; перегоны видны всё
   время и после отпускания пересчитываются по новому порядку; учитывать обратный порядок отображения
   (переключатель сортировки) — перестановка в данных `moveStation(from, to)` с учётом разворота.
   Свайп влево «Удалить» работает только вне перетаскивания.
2. **Секции локомотива** (форма локомотива): долгое нажатие в любом месте карточки секции; нумерация
   «Секция N» — по новому порядку; это изменение формы (сохраняется). Порядок секций — часть данных:
   отправляется на сервер порядком массива (сервер хранит `position`); при синке не перемешивать.
3. **Плитки текущего маршрута на главной** (Локомотив / Поезд / Пассажиром / На работе): долгое нажатие
   включает режим перестановки — все плитки покачиваются (±1,2°, 110 мс), удерживаемая увеличивается до
   1,04, не качается и едет за пальцем; соседи меняются на половине ширины. Режим остаётся после
   отпускания — следующие плитки можно тянуть сразу, без долгого нажатия; клики по плиткам и «+» в режиме
   отключены; касание вне секции «Текущий маршрут» завершает режим и не выполняет действие под касанием.
   Порядок (ключи `work`, `loco`, `train`, `passenger`) хранится **только локально** (localStorage),
   не синхронизируется; пока не меняли — «На работе» первой, затем заполненные, затем пустые.
4. **Промежуточные станции плеча** (редактор плеча, §6.6): в режиме «Изменить» — за ≡ и долгим нажатием;
   после перестановки км станций не пересчитываются автоматически (их обновляет «Измерить по карте»),
   изменения уходят автосохранением плеча.

### Проверка
- В каждом списке: долгое нажатие → перенос через 2–3 позиции → порядок сохранился после перезагрузки
  (кроме плиток — они локальные, но тоже после перезагрузки страницы).
- Обычная прокрутка без долгого нажатия не начинает перетаскивание; свайп «Удалить» и тапы работают как раньше.
- Секции/станции, переставленные в PWA, приходят на Android в том же порядке и наоборот.
