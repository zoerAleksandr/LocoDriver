## Рабочий цикл на каждое изменение

1. **Постановка.** Уточни у пользователя желаемое поведение; если меняется JSON-контракт сервера — остановись
   и спроси (старые Android-клиенты в проде, обратная совместимость превыше всего).
2. **Эталон.** Сначала запиши поведение в `SCREEN_SPECS.md` (тексты побуквенно, числа, состояния), потом
   строку/строки в `docs/MAP_PARITY.md` со статусом ⬜. Изменения спеки вноси через ветку и сливай в `master`
   (`git -C <основная папка> merge …` только если папка чистая; не пушить).
3. **Раздача.** Сначала сервер (если нужен), затем Android и PWA параллельно. В каждом задании: ссылка на
   раздел спеки, что сделать, что НЕ делать (см. «Жёсткие правила»), как проверить, куда доложить.
4. **Приёмка.** По каждой строке: прочитай диффы, прогони тесты/сборку, сверь тексты и числа с эталоном
   (так нашлись «Нет связи» против «Не удалось связаться»), по возможности проверь вживую (эмулятор Android /
   браузер PWA / запрос на проде). Только потом ставь ✅ и уровень проверки (К/Т/Ж).
5. **Отчёт пользователю.** Что совпадает, что отличается и почему, что ждёт его команды.

## Жёсткие правила (передавай их в каждое задание)

- **Не пушить и не деплоить** ни Android (`master`), ни PWA, ни прод без явной команды пользователя
  («запушь», «задеплой»). «Продолжай» — не разрешение.
- Контракт сервера менять нельзя без согласования; поля только добавлять, сервер должен сохранять поля,
  которые старый клиент не прислал. Деплой сервера — до клиентов.
- Новые зависимости (библиотеки) — только после согласия пользователя.
- Не логировать координаты и персональные данные (email, vk_id, токены).
- Тестовые данные на реальном аккаунте пользователя не создавать (формы поезда/локомотива сохраняются сразу
  в настоящий маршрут); на эмуляторе — реальный прод-аккаунт.
- В коммитах Android-репо не добавлять `Co-Authored-By`.
- Любая правка Android, затрагивающая описанный в `SCREEN_SPECS.md` экран, — в том же коммите правка спеки.
- Не смешивать две сессии в одной рабочей папке; не трогать чужие незакоммиченные изменения.

## Известные грабли (уже наступали)

- Ложный успех: `nginx -t`/`reload` на проде проверяли старый файл (см. выше про bind-mount).
- Прокси тайлов кэширует без учёта `Accept-Encoding`: Brotli в кэше ломает карту Android (шрифты).
- Сохранённая на устройстве линия плеча устаревает при обновлении графа: всегда запрашивать с сервера,
  сохранённая — только запас без сети.
- Граф путей на сервере: пересборка `python3 ops/osm_rail/build_rail_data.py --work ~/osm_rail --out
  ~/osm_rail/rail.sqlite --no-download`, файл кладётся в контейнер `/data/osm_rail/rail.sqlite`.
- Лимит запросов фичи — 200/час на пользователя (429 + `Retry-After`).
- Эмулятор Android: если сеть «пропала» — перезапустить с `-dns-server 8.8.8.8,8.8.4.4`.
