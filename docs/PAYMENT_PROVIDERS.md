# Платёжные провайдеры: роли

> Решение от 27.09.2026. Подробности интеграций — `docs/CKASSA_INTEGRATION.md`,
> поведение экранов — `SCREEN_SPECS.md` §19, §32.1, §32.1b.

| Провайдер | Роль | Что даёт |
|---|---|---|
| **Robokassa** | **Основной** способ оплаты подписки «Машинист Pro» | Разовая оплата + **рекуррентные платежи (автопродление)** |
| **CKassa** | **Резервный** способ оплаты | Разовая оплата по ссылке (хостовая страница CKassa). Рекуррент через CKassa не развиваем |

## Что это значит для клиентов

- Кнопка оплаты на экране Покупок ведёт в Robokassa (Android:
  `PurchasesViewModel.USE_CKASSA = false`). С версии с автопродлением Android, как
  PWA и iOS, платит через **серверный checkout** (`POST /v1/payment/checkout` →
  страница Robokassa в браузере): встроенный SDK и пароли мерчанта из приложения
  убраны. После распространения этой версии пароли Robokassa можно сменить.
- CKassa остаётся включённой на сервере (`/v1/payment/ckassa/*`) как запасной
  путь, если Robokassa недоступна.
- **Впереди:** ссылка «Оплатить резервным способом» — переход к оплате через
  CKassa (`POST /v1/payment/ckassa/checkout` → ссылка оплаты). Где показывать
  и при каком условии (всегда / только при ошибке Robokassa) — решить при
  реализации. Задача — в `TASKS.md`.
- Подтверждение оплаты для обоих провайдеров одинаковое: запись ожидаемой
  оплаты + проверка срока с сервера при любом возврате в приложение
  (`PaymentReturnChecker`, SCREEN_SPECS §32.1b).

## Страница возврата CKassa (`/v1/payment/ckassa/success|fail`)

Сейчас для Android/iOS эндпоинт отдаёт JSON `{"result":"success"}`, для PWA
(`?source=pwa`) — редирект на `app.locodriver.ru/payment?status=…`.

Почему на неё нельзя полагаться как на гарантию возврата в приложение:

- Ссылку на неё мы CKassa **не передаём**: `invoice/create2` не принимает
  `successUrl`. Переход (если он вообще настроен) задаётся на стороне CKassa для
  услуги — уточнять у менеджера. Без этого пользователь после оплаты видит
  собственную страницу CKassa, а не нашу.
- Даже при настройке она откроется **только в той вкладке браузера, где шла
  оплата**, и только когда CKassa увидит финальный статус. Если пользователь
  оплатил в приложении банка (СБП) и вернулся сразу в наше приложение, вкладка
  с редиректом может так и не открыться.
- Кнопка «Вернуться в приложение» (`locodriver://…`) на такой странице
  сработает только по нажатию: браузеры блокируют автопереход на свою схему без
  действия пользователя.

Итог: страница — только удобство (понятное «Оплата прошла» + кнопка возврата).
Гарантию «Платёж принят!» даёт клиент (§32.1b). С учётом резервной роли CKassa —
низкий приоритет.
