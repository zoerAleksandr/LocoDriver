# Передача работы: реферальная программа

## Ветки и расположение

- Клиент: `codex/referral-client` в этом репозитории.
- Сервер: `codex/referral-server` в репозитории `proxy-parser`. Работа выполнена в изолированном клоне `/private/tmp/locodriver-referral-server`; перед продолжением проверьте наличие этой ветки в исходном серверном репозитории.
- Ничего не развёрнуто на продакшене, миграция БД не запускалась.

## Принятые правила

- Бонус только после **первой подтверждённой оплаты** приглашённого. До программы `user_settings.subscriptionPeriod == 0` означал, что оплат ранее не было. После начисления бесплатного реферального срока неплативший пользователь может иметь ненулевой период. Поэтому серверная миграция заполняет `user_first_payment` для прежних аккаунтов с ненулевым сроком, а callback каждой будущей первой оплаты создаёт отметку атомарно с платежом.
- Код может применить уже зарегистрированный пользователь до первой оплаты. Нельзя свой код или два разных кода.
- Размер бонуса окончательный: каждому половина срока оплаченного тарифа, точно в миллисекундах. Общего лимита приглашений нет; одно приглашение на приглашённого. При возврате бонус отменяется у обоих, а повторная покупка не считается первой заново.

## Обязательное до выпуска

1. **CKassa:** callback сейчас сопоставляет pending-счёт по `email + amount`, выбирая последний. Если пользователь открыл два неоплаченных счёта на одну сумму, может быть выбран не тот тариф. Узнать у менеджера CKassa, возвращается ли в `invoice/create2` ID инвойса и передаётся ли тот же ID в callback; если нет, можно ли добавить наш уникальный `payment_intent.id` в реквизит/метаданные callback. Без этого нужна другая однозначная схема сопоставления или ограничение активных счетов. Реферальный код дополнительных параметров провайдера сам по себе не требует.
2. **Серверные тесты:** тестировать миграцию, повторные webhook обоих провайдеров, конкурирующие платежи, одну первую оплату, собственный/неверный/второй код, отсутствие настроек и откат всей транзакции. Проверить случай: пользователь получил бонус за приглашение до собственной первой оплаты и затем применил чужой код. Локально `python3 -m pytest` недоступен; `compileall` прошёл. Локальная Python 3.14/SQLModel-среда не может импортировать даже исходные модели (`Column object updated_at already assigned`), нужна проектная среда Python 3.9 из Docker/CI.
