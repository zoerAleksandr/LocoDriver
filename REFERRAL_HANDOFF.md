# Передача работы: реферальная программа

## Ветки и расположение

- Клиент: `codex/referral-client` в этом репозитории.
- Сервер: `codex/referral-server` в репозитории `proxy-parser`. Работа выполнена в изолированном клоне `/private/tmp/locodriver-referral-server`; перед продолжением проверьте наличие этой ветки в исходном серверном репозитории.
- Ничего не развёрнуто на продакшене, миграция БД не запускалась.

## Принятые правила

- Бонус только после **первой подтверждённой оплаты** приглашённого. До программы `user_settings.subscriptionPeriod == 0` означал, что оплат ранее не было. После начисления бесплатного реферального срока неплативший пользователь может иметь ненулевой период. Поэтому серверная миграция заполняет `user_first_payment` для прежних аккаунтов с ненулевым сроком, а callback каждой будущей первой оплаты создаёт отметку атомарно с платежом.
- Код может применить уже зарегистрированный пользователь до первой оплаты. Нельзя свой код или два разных кода.
- Размер бонуса предварительный: каждому половина срока оплаченного тарифа, точно в миллисекундах. Лимит приглашений пока не установлен; одно приглашение на приглашённого.

## Обязательное до выпуска

1. **CKassa:** callback сейчас сопоставляет pending-счёт по `email + amount`, выбирая последний. Если пользователь открыл два неоплаченных счёта на одну сумму, может быть выбран не тот тариф. Узнать у менеджера CKassa, может ли callback возвращать уникальный ID нашего счёта; если нет — спроектировать однозначное сопоставление или строгую блокировку нескольких активных счетов. Реферальный код дополнительных параметров провайдера сам по себе не требует.
2. **Серверные тесты:** тестировать миграцию, повторные webhook обоих провайдеров, конкурирующие платежи, одну первую оплату, собственный/неверный/второй код, отсутствие настроек и откат всей транзакции. Локально `python3 -m pytest` недоступен; `compileall` прошёл. Локальная Python 3.14/SQLModel-среда не может импортировать даже исходные модели (`Column object updated_at already assigned`), нужна проектная среда Python из Docker/CI.
3. **iOS:** компиляция `:iosApp:compileIosMainKotlinMetadata --offline` остановилась до исходников из-за отсутствующих в кеше `kotlinx-coroutines-core-iossimulatorarm64` и `atomicfu-iossimulatorarm64`. Проверить Kotlin framework и SwiftUI в Xcode. iOS `PurchasesView` уже был заглушкой без реальной оплаты; реферальное поле не заменяет эту незавершённую оплату.
4. **Платежи:** проверить, что переход Robokassa на `payment_transaction` не меняет ответ старым клиентам и корректно обрабатывает существующие `InvId`. Прогнать интеграционные тесты в тестовом контуре, не на продакшене.
5. **Кабинет:** проверить защиту админ-сессией, поиск/пагинацию, отображение дат в часовом поясе владельца и реальные сроки до/после в читаемом формате. Добавить тесты доступа.
